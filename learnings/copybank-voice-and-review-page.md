# Copy bank: voice standard and the review page

## Voice (set 2026-08-21, replaces the original literary bank)
- **One instruction per push, verb first.** "Play {item} for {min} minutes." Not "There is
  room for one deep breath, and that is where {item} starts."
- **Spoken words only.** play / stop / rest / sleep / break / quiet. Not fraying, unclench,
  atmosphere, texture, stimulation. Target reader is a mass Indian audience reading English
  as a second language on a phone, once, at a glance.
- **Warmth comes from what is said, not from softening how it is said.** Direct is the brief;
  scolding is not. No line may imply the member has already failed.
- Still banned: guilt, sleep-deprivation scare copy, urgency/scarcity, medical claims,
  Hindi/Hinglish, exclamation marks (hard-gated only for `night_nidra`, but absent everywhere).

## Gotchas the validator enforces (`bun run scripts/validate-copybank.ts`)
- Lengths are checked **after substituting the longest item title the slot can serve**. With
  `NIDRA_API_URL` unset it falls back to `Evening Wind Down` / 27 min, which is longer than
  anything shipping — passing locally means passing in CI.
- Titles and bodies must be globally unique across all 5 slots, not just within a slot.
- Max one emoji per variant, counted over title+body together.
- `\b[A-Z]{3,}\b` anywhere is an error, so no acronyms in copy.

## Slot facts worth remembering when writing
- `morning_focus` (10:00) serves **both** Focus Breathing and Yog Nidra, so breath-specific
  imagery is only half-true — it reads as a lean, not a bug.
- Soundscapes have **no voice**: never write "follow the voice" in the 14:00 / 19:00 slots.
- `night_nidra` fires at 21:30, when most members are not lying down yet — "you are already
  in bed" framing does not hold.
- Do not hardcode catalog names (Rain, Waves) in copy; the pool changes, `{item}` does not.

## The review artifact
- The reviewer-facing page is **generated**, not hand-written: it renders every variant from
  `config/copybank.json` into phone-notification previews with a live `{item}`/`{min}` picker.
- It lives at artifact `1d64e169-a95b-4621-8c03-b26aa8fc8628`. Republish with that URL as
  `url` or a new artifact is created instead of updating it.
- Real item titles/durations in the picker come from the live catalog, not from the repo —
  they were captured into the generator by hand.

## The review page is now generated by a repo script
- `bun run build-review` → `scripts/build-review-page.ts` reads `config/copybank.json` and writes
  `review/copybank-review.html`. Inputs: `review/review.css`, `review/review.js`,
  `review/history-section.html` (static analysis appended verbatim at the end of the page).
- Every variant carries an **Accept / Reject** toggle; clicking the standing verdict clears it.
  State lives in `localStorage` under `nidra-copybank-decisions-v1`, wrapped in try/catch — a
  private window or blocked site data must not break the page. The page prints the accepted and
  rejected id lists as plain text so a reviewer can hand them back.
- Real catalog titles/durations for the `{item}`/`{min}` picker are hardcoded in the generator's
  `SLOTS` table — they come from the live catalog, not the repo, so they need a manual refresh
  when the catalog changes.
- Republish with `url: https://claude.ai/code/artifact/1d64e169-a95b-4621-8c03-b26aa8fc8628`.

## Decisions are shared through the page itself (2026-08-21)
- **localStorage is a dead end for handing verdicts back.** It is per-viewer, per-browser, and
  unreadable by anyone else — including Claude. A reviewer's picks stayed stuck on their machine.
- Fix: the artifact declares `capabilities: {artifact: {}}` and the page **republishes itself** on
  Save via `artifact.publish(html)`, with the verdicts embedded as
  `<script id="verdicts" type="application/json">{"verdicts":{id:"accept"|"reject"},"savedAt":…}</script>`.
  Reading them back is then just WebFetch on the artifact URL and a grep for that script tag.
- Two-layer state on purpose: **saved** = the blob in the published version (shared); **draft** =
  this viewer's unsaved changes in `localStorage` (`nidra-copybank-draft-v2`). The Save button
  shows the dirty count; each card shows an `unsaved` badge until it is published.
- `publish()` needs the COMPLETE page and must never serialise the live DOM (it holds the rendered
  cards, the viewer's draft, and the injected frame runtime). So the page keeps its static markup in
  `<template id="shell">`, its CSS in `<style id="css">` and its own code in `<script id="app-js">`,
  and rebuilds a clean document from those three. Anything inlined that way must not contain a
  literal `</script>` — the generator throws if it does, and `app.js` writes `<\/script>`.
- Publishing runs with the **viewer's** authority: a view-only teammate gets `not_writer` /
  `not_granted` on the first Save, so the page must degrade to "copy these lists" rather than look
  broken. They need edit access from the artifact's share menu to save.
- `document.querySelectorAll('.card')` was wrong once the history section landed — it reuses `.card`
  for the 41 shipped sends. Scope every verdict query to `#slots .card`.
- Rebuilding with `bun run build-review` resets the verdict blob to empty. **Read the saved
  decisions off the live page before regenerating** mid-review.

## Reviewer decisions travel by copy-paste, not by self-publish (2026-08-21)
The self-publishing version (page calls `artifact.publish()` on Save) was **removed**. It worked,
but it had a design fault and an operational trap:

- **Whole-set overwrite.** Each Save published that viewer's entire local set as the shared truth,
  so any stale tab or second writer silently dropped everyone else's verdicts. Symptom to
  recognise: `savedAt` advances on every save while the verdict count stays frozen or snaps back.
  A merge (`{...shared, ...myEdits}`, with a `clear` tombstone for removing a shared verdict) fixes
  it — that code is in git history if shared state is ever wanted again.
- **You cannot iterate on a self-publishing artifact from here.** Deploy demands that this session
  has read the current version through the **plain** artifact URL, but WebFetch caches that URL for
  ~15 min, so while a reviewer keeps saving it serves an older copy — and a cache-busted URL
  (`?r=2`) fetches the right bytes without registering as the baseline. `force:true` is refused too
  (`deploy 400: this artifact self-publishes — provide the baseVersion you edited from`). Net
  effect: republishing is blocked until the cache expires. Do not retry in a loop.

Current design: verdicts live in `localStorage` (`nidra-copybank-edits-v3`) and leave as **text**.
`Copy my N decisions` builds a Slack-ready block (counts header, then `ACCEPTED` / `REJECTED`
sections of `id  title`) and tries `navigator.clipboard.writeText`, then a hidden-textarea
`execCommand('copy')`, then prints and selects the text — a sandboxed frame can refuse both.

**Always read the live blob before rebuilding.** `review/verdicts.json` seeds the page, and
`bun run build-review` carries it forward — but a rebuild from an empty file wipes the record. The
first real pass (37 rejects, 15:26) was only saved because the pre-publish read caught it.
